# v1.0.1 maintenance

## Requirement

v1.0.1 closes the installer tag gap and makes the repository independently
maintainable by a new developer and a fresh Codex session. It must not change
application behavior, commercial authorization, frozen releases, or servers.

## Design

The installer default becomes `v1.0.1`, and stable documentation uses the fixed
raw Tag URL. Root `AGENTS.md`, auto-discovered `.agents/skills`, development
history, architecture, decisions, verification, bootstrap, and handoff checks
become repository-owned context. Skills route to maintained docs instead of
copying large bodies of prose.

## Release strategy

Backend, initializer, and frontend are reused byte-for-byte from v1.0.0. New
metadata records `release_version=v1.0.1`, the new release commit, and application
build commit `f25dcb4576eea367afb0274f4b21b6c02c735984`; the manifest is regenerated.

## Verification and current status

Local gates include all Go tests/builds, frozen frontend install/lint/build,
migrations, installer, Skills validation/discovery, handoff links, current and
history secret scans, commercial boundary, binary identity, and an isolated
Codex cold start. Until they actually pass and GitHub publication completes,
v1.0.1 status is `IN DEVELOPMENT`, not released.

## Constraints

Remote write requires a securely rotated GitHub credential. Do not use a known
exposed token. Do not redeploy any panel or Agent as part of this release.
