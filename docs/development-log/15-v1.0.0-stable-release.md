# v1.0.0 stable release

## Goal and decision

After remote install and functional acceptance, the same tested commit and
application artifacts were promoted from `fvdx-remote-rc1` to the first stable
release. No new source or rebuild was allowed during promotion.

## Result

Annotated tags `fvdx-remote-rc1` and `v1.0.0` peel to
`f25dcb4576eea367afb0274f4b21b6c02c735984`. Backend and frontend assets are
byte-identical between RC and stable. The RC remains a pre-release and its
history/assets remain intact. v1.0.0 became Latest and was protected by a rule
matching only `refs/tags/v1.0.0`, prohibiting update and deletion.

## Known release gap

The source installer still defaulted to `fvdx-remote-rc1`. Functionally the
artifacts were identical, but the normal main-branch curl command did not claim
the stable tag. This was reported rather than hidden and became v1.0.1 scope.

## Maintenance rule

Never move, delete, edit, rebuild, or replace v1.0.0. A later stable version is a
new commit/tag/release with separate protection. Production deployment was not
part of stable publication and must not be inferred.

Sources: GitHub tag/release/ruleset audit and anonymous asset comparison.
